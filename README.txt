Project Overview
----------------
The server sends one requested text file to the client using IPv4 UDP. The
server is the Go-Back-N (GBN) sender; the client is the GBN receiver. DATA
packets contain one line of the input file, with at most 80 data bytes. The
client writes accepted data to out.txt. REQUEST, DATA, ACK, and EOT packets use
a six-byte header containing the packet type, data count, and sequence number
in network byte order.

Files
-----
client.c
    Requests a file, accepts in-order DATA packets, writes them to out.txt,
    sends cumulative ACKs, and acknowledges EOT packets.

server.c
    Receives a file request and sends DATA packets with a Go-Back-N window,
    timeout retransmissions, and reliable EOT handling.

packet.c
    Serializes packet fields in network byte order and deserializes packets
    after checking their header, payload count, and total length.

packet.h
    Defines packet types, the maximum payload and header sizes, the packet
    structure, and serialization function declarations.

lossy.c and lossy.h
    Instructor-supplied files, unchanged. They provide deterministic UDP packet
    loss simulation through lossy_init() and lossy_sendto().

Makefile
    Builds both server and client with the default target. "make clean" removes
    the executables and object files.

README.txt
    Describes the project, files, build and run steps, and GBN behavior.

empty.txt
    Empty-file test input.

one.txt
    Single-line test input.

torture_test.txt
    Multi-line test input with blank lines, a long line, and a final line
    without a newline.

out.txt
    Generated by the client in its working directory. It is an output file,
    not a submission source or test input; remove it from the submission.

Compilation
-----------
Use a Linux system with gcc and make. From the project directory, build both
programs by running:

    make

The Makefile creates the server and client executables.

Execution
---------
Run the server from the directory containing the requested input file. The
server command-line format is:

    ./server <port> <window-size> <timeout-ms> <data-loss-rate> <seed>

Run the client in a second terminal. The client command-line format is:

    ./client <server-host> <port> <timeout-ms> <ack-loss-rate> <seed>

The server port must be 1024 through 65535, the window size 1 through 65534,
and the timeout a positive number of milliseconds. Each loss rate is in the
range [0.0, 1.0); the seed is an integer. When prompted, enter the requested
filename. The client creates or overwrites out.txt in its current directory.

Go-Back-N Sender
----------------
The server maintains these values:

    base
        Sequence number of the oldest DATA packet that has not been
        cumulatively acknowledged.

    next_seq
        Sequence number to use for the next DATA packet that has not yet been
        sent.

    window_size
        Maximum number of outstanding DATA packets the server may have sent
        without receiving acknowledgments.

    timer
        One monotonic timer for the oldest outstanding packet at base. It
        starts when the first packet enters an empty window. If an ACK advances
        base and packets remain outstanding, the timer is restarted for the new
        base. It is not restarted for duplicate or stale ACKs.

The server sends packets while the window has room, which is when
next_seq < base + window_size. ACK n is cumulative: it acknowledges every
DATA packet through sequence number n. A valid ACK advances base to n + 1.
ACKs for packets that are stale, duplicated, or not yet sent do not move the
window.

When the timer expires, the server increments its timeout statistic and
retransmits every outstanding DATA packet from base through next_seq - 1 using
lossy_sendto(). It increments the data retransmission count for each packet
retransmitted, then restarts the timer.

Receiver and Duplicate Packets
------------------------------
The client starts with expected_seq equal to 1 and accepts only the DATA packet
whose sequence number matches expected_seq. It writes that packet once,
advances expected_seq, and sends an ACK for the accepted sequence number.

Duplicate and out-of-order DATA packets are discarded and not buffered. The
client resends its most recent cumulative ACK; before accepting packet 1, that
ACK has sequence number 0. This allows the server to learn which DATA packet
was last accepted and retransmit as needed.

End of Transfer
---------------
After all DATA packets are acknowledged, the server sends an EOT packet whose
sequence number is the next DATA sequence number. The server starts a timeout
for EOT and retransmits it until it receives an ACK with the same sequence
number.

When the client receives the expected EOT, it closes out.txt, sends the EOT
ACK, and enters a linger period lasting twice the configured timeout. If the
EOT ACK was lost, the server retransmits EOT; the client recognizes the
duplicate, sends the EOT ACK again, and restarts its linger period. The server
terminates after receiving the EOT ACK, and the client terminates after a full
linger period passes without another EOT.

Example Run
-----------
Run the server command in one terminal and the client command in a second
terminal. At the client prompt, enter the name of a file in the server's
working directory.

./server 9000 4 1000 0.0 1
./client 127.0.0.1 9000 1000 0.0 1
